# AI usage

This prototype, research synthesis, tests and documentation were created with a Codex coding assistant. The entries below document choices made during that assisted workflow. They are **not** claims that a human author independently wrote or personally validated every line. The submitting author should review, run and understand the work before presenting it.

| Decision | AI-assisted proposal | Accepted / rejected and why | Verification / limitation |
| --- | --- | --- | --- |
| Meaningful artifact | Use a structured notebook instead of an unconstrained answer box or a diagram editor. | Accepted: assumptions, responsibility ownership and behaviour provide minimum review context; richer sections remain optional so drafts stay easy. | Minimum context and format edge cases are tested. Character counts cannot establish meaningful reasoning. |
| Explainable evaluation | Start with six deterministic text checks, exact evidence and actionable prompts behind an evaluator contract. | Accepted for reproducibility. Rejected treating keyword matches or pattern names as a design-quality grade. No LLM response is simulated. | Tests cover exact evidence, omitted sections, substring matches and negated phrases. UI states the evaluator's limitations. Semantic usefulness still needs learner/expert testing. |
| Attempt lifecycle | Model `Attempt` as an aggregate with immutable submissions and parent-linked revisions. | Accepted: revisions should not erase the baseline. A mutable single answer would make improvement difficult to inspect. | Tests verify invalid transitions, copy isolation, comparison, duplicate submit and stale draft conflicts. |
| Practical async work | Use one process, SQLite-backed statuses and a small evaluator worker. | Accepted. Rejected infrastructure-heavy scheduling for a two-day exercise. Retry and timeout matter more than distributed scaling here. | Tests cover provider error, timeout, malformed response, late completion, durable restart recovery and queue draining. One process per database is a deliberate constraint. |
| Research and reliability | Browse official product documentation; turn research observations into limited product hypotheses and challenge the implementation with failure tests. | Accepted. Rejected invented interviews, competitor feature-absence claims and measured learning outcomes without evidence. | Source links are in the research note. The first test run exposed two test-harness issues: fetch rewrote the Host header, and Windows file cleanup occurred before closing SQLite. Tests were corrected to exercise the real transport and close storage before cleanup. |

AI helped generate the implementation and explanatory material; it did not supply evidence of learner effectiveness. The app itself makes no AI API calls. A future LLM evaluator requires credentials, disclosure, expert-reviewed examples, prompt-injection defenses and semantic calibration before its feedback can be trusted.
